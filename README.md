# 波波酪梨 · 出貨通知系統 — 部署與使用

版本 v1.1.0　更新於 2026-08-13

---

## 部署順序（不能反）

### 1. 試算表

照 `試算表設定.md` 做完三件事：訂單資料加 R 欄、新增「集點連結」分頁、新增「出貨通知」分頁。

**先驗收公式**再往下走。文案不對，後面全都不用測。

### 2. GAS（獨立專案，不要動 code.gs）

1. script.google.com → 新增專案 → 命名「波波酪梨_出貨通知」
2. 貼上 `shipping.gs`
3. 專案設定 → 指令碼屬性 → `SHIP_TOKEN` = 自訂長字串
4. 編輯器直接執行 `測試取清單()`，看執行紀錄確認箱數／斤數／點數都對
5. 部署 → 新增部署作業 → 網頁應用程式（執行身分：我；存取權：任何人）
6. 複製網址備用

> 用獨立專案的理由：一個 GAS 專案只能有一個 `doGet`，而且產季中重新部署訂單後端有風險。這支只讀不寫，對 `code.gs` 零影響。

### 3. GitHub Pages（獨立 repo）

**不要放進 `Shop`。** 這支工具的迭代期就在產季正中間，放進 `Shop` 會讓每次改文案、調字級都觸發整個店面重新建置；而且 `sw.js` 若 scope 設錯，客人會拿到被快取的舊版店面，這種失敗你在自己手機上看不出來。分開就從結構上不可能發生。

1. 新增 repo：`probro-shipping-notice`（Public）
2. 把 `pwa/` 裡的七個檔案放**根目錄**，不要放子資料夾：

```
probro-shipping-notice/
  index.html
  app.js
  sw.js
  manifest.json
  icon-192.png
  icon-512.png
  icon-512-maskable.png
  README.md
```

3. Settings → Pages → Source 選 `main` / `(root)`

網址：`https://probroavocado.github.io/probro-shipping-notice/`

放根目錄的理由：SW scope 就是整個站，沒有子路徑的坑，`manifest.json` 的 `./` 相對路徑也不用改。

**Public 沒問題**：token 只存在手機的 localStorage，照片全程不離開裝置，程式碼公開不洩漏任何東西。

### 4. 裝到手機

用 **Safari**（Chrome 不行）開上面的網址 → 分享鈕 → 加入主畫面。

第一次開啟會停在設定頁，填入 GAS 網址與 token → 儲存並測試連線。

> **若之後換過網址**：不同網址等於不同 origin，各自有獨立的 IndexedDB。舊 icon 一定要刪掉，否則照片會分散在兩個 App 裡——那是最容易搞丟存證版的情況。

## 日常流程

**出貨前（有訊號）**
1. 試算表篩出今天要出的，R 欄整欄貼「出貨準備」
2. 開 App → 重新抓取 → 確認筆數對

**出貨現場（可離線）**
3. 手寫姓名 → 組箱 → 點卡片選人 →（多箱才）選箱 → 拍照
4. 多箱訂單拍完會自動跳下一箱，不用退出重選
5. 收工前看清單底部的紅字警告，確認沒有漏拍

**回家／有空時段**
6. 出貨頁上方紅色提醒 →「存到相簿」→ 分享選單選「儲存 N 張影像」
7. 通知頁 → 重新抓取文案 → 逐筆按「傳送」
   - 文案自動進剪貼簿，分享選單帶著照片
   - 在 LINE 選聊天室 → 送出照片 → 長按輸入框貼上文案
8. 回試算表把 R 欄改「已出貨」

## 設計上刻意做／刻意不做的事

**做了**
- 資料時間戳永遠顯示在右上角，超過 3 小時轉紅字。抓取失敗時明講「沿用 14:30 的資料」，不靜默給舊的。
- 卡片左側色條與圓點直接反映拍攝進度（灰＝未拍、黃＝部分、綠＝完成）。
- 收工前列出沒拍完的訂單姓名與缺幾箱。這是順序假設做不到的事——它不知道該有幾張。
- Q 欄解析出的箱數與第一行宣告的「共 N 箱」不符時，直接在 App 上標示要人工確認。
- 試算表沒有文案的訂單，在通知頁用紅字標出來，不會讓你傳出一則空訊息。
- 集點超出已建連結範圍時，「需人工發放」寫在文案本體裡，複製時一定看得到。
- 「臨時加入」的訂單用棕色標籤標示，提醒你回試算表補標記。
- 照片沒存到相簿時，出貨頁常駐紅色提醒並附一鍵存檔按鈕。

**沒做**
- 不 OCR 手寫簡碼。手寫的定位是給你肉眼校驗，不需要機器讀懂。
- 不自動回寫試算表狀態。現場只讀不寫，離線才可靠，回填用篩選整欄貼上更快。
- 不做自動重試。抓不到就明講，你自己決定要不要再按。
- 照片與文案都不印託運單號。單號交件後才有，而綁定已在現場完成。

## 已知限制

| 限制 | 說明 |
|---|---|
| 只保留疊字版 | v1.1 起不再另存未編輯的存證版。疊字方塊在畫面上方、不遮酪梨本體，舉證仍成立，但檔案本身是編輯過的。 |
| 沒有 EXIF | 照片是從相機預覽取幀再編碼，不含 EXIF。拍攝時間由 App 記錄在資料庫。 |
| 資料可能被系統清除 | iOS 儲存空間吃緊時會清 IndexedDB。**當天存到相簿**是唯一保險。 |
| 只能用 Safari 安裝 | Chrome 開的加不進主畫面。 |
| 更新要重開 | 改版後要完全關閉 App 再開。版本號在設定頁最下方，用來確認跑的是哪一版。 |
| 傳送要兩個動作 | iOS 無法一次把圖片和文字都送進 LINE。文案走剪貼簿，照片走分享選單。 |
| 一次最多 40 筆未出貨 | 「臨時加入」的搜尋結果上限，避免清單過長。用姓名搜尋即可。 |

## 改版時

- 改 `app.js` 或 `index.html` → **一定要同時改 `sw.js` 的 `CACHE` 名稱**，否則舊快取不會淘汰，你會以為改了但手機上還是舊的。
- 改 `shipping.gs` → 要**建立新的部署版本**，存檔不夠。
- 改 `格式化裝箱明細_()` 的輸出格式 → `shipping.gs` 的 `解析裝箱_()` 與試算表 G 欄公式都要跟著改。這是目前唯一一處需要三邊同步的地方。
